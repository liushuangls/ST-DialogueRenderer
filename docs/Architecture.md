# 对话渲染系统 2.0 架构

## 数据流

`index.js → extension.js` 负责宿主接入和对象装配。模型输出通过酒馆自身的显示正则、Markdown 和清理流程，随后由 `controller.js → dom-renderer.js` 装饰消息 DOM。

`protocol.js` 同时定义两种行头、解析结果和固定提示词。解析只消耗前两个字段分隔符；正文中的 Markdown、方括号和竖线保持原义。解析结果区分普通文本、有效对话、不完整尾行和无效标记。固定协议不可通过配置替换，补充要求存入独立字段。

## 模块

| 模块 | 职责 |
| --- | --- |
| `config.js` | 默认样式、情绪分组、词表验证和样式快照 |
| `context.js` | 宿主上下文、角色卡稳定身份和资源键 |
| `protocol.js` | 对话语法、诊断、固定提示词和补充要求 |
| `storage.js` | IndexedDB、资产事务、配置与导入导出 |
| `sync.js` | 头像和全局样式同步、修订与冲突处理 |
| `zip.js` / `image-utils.js` | 图片备份封装和可选压缩 |
| `fonts.js` | 字体目录、请求去重、页面内缓存与显式刷新 |
| `assets.js` | 保存样式、预览差异、头像缓存和字体 DOM 资源 |
| `controller.js` | 最近 AI 消息范围、正文变化、投影生命周期 |
| `dom-renderer.js` | 保留富文本的气泡装饰、原始节点恢复与样式应用 |
| `manager-panel.js` | 按需加载的管理界面，通过回调访问运行时 |
| `extension.js` | 提示词注入、设置面板、状态和资源生命周期 |

界面不再承担字体目录服务；渲染和存储不依赖管理面板。旧脚本的父窗口查找、全局 API 别名、协议迁移和无效 Markdown 模式已移除。

## 视图所有权

原始 DOM 节点由 decorator 记录，关闭、移出近期范围或内容卸载时原样恢复；聊天原文始终由宿主管理。异步头像完成前检查视图存活状态，避免向已释放内容写入。

静态模式的 MutationObserver 只将正文变化和消息挂载/移除标为需要处理。自己的气泡资源变化、消息计时和其他元数据不安排新的渲染。更新在动画帧内合并。

ChatSurface 模式在首次投影前同步注册 participant，使用 `didCommitContent` 的 signal 和 disposer；不同时启动静态 DOM 观察。流式结束会重新检查暂未完成的标记，即使没有最后一次 DOM 替换。

## 配置、预览与字体

`RenderAssets.savedSettings` 是已保存配置，`preview` 只记录相对打开面板基线真正改动的字段。预览不写数据库；关闭时同步清除差异并恢复视图。保存和远端应用后重新读取保存值，避免覆盖另一个设备改动的字段。

文字颜色由根节点模式和每个角色的 CSS 变量共同决定，切换全局色与角色色不残留行内文本颜色，也不需要重建气泡。

字体目录请求按 URL 合并，成功结果在页面内复用，显式刷新才重新请求。字号和颜色预览不触发字体同步。字体资源按目录、CSS 来源和本地记录元数据生成签名；签名未变时保留节点与 Blob URL。异步请求使用独立修订，旧请求不能覆盖新的字体选择，卸载时中止请求并撤销资源。

## 数据事务与格式

角色重命名在同一 IndexedDB 事务中移动基础头像、所有情绪差分和主题色。目标名字已有任一资源时事务中止。成功提交后才撤销旧 Blob URL，并让同步层发送原名删除与新名写入。

提示词模板的补充文本和情绪词表先完整验证，再在同一事务内保存。模板格式使用 `version: 2.0` 和 `protocolVersion: 2`。图片与样式的存储、备份和同步格式保持各自的数据版本；对话协议版本不要求重建资产库。

2.0 不解析 `@bubble` 或旧容器别名，不读取旧自由格式提示词配置；已有聊天不会被迁移或改写。

## 验证

多设备存储与同步测试通过 Node 的隔离 ESM context 运行实际模块。浏览器回归验证真实 CSS 颜色、富文本、界面加载和预览撤销。发布脚本从唯一的包版本生成 manifest 与模块依赖版本，检查同时验证动态导入。
