# 对话渲染系统

用于 SillyTavern / TauriTavern 的前端扩展，把 `@bubble` 角色台词和心理活动显示为带头像、情绪标签的对话。由原「对话渲染系统 v8.10」脚本迁移。

## 安装与更新

在酒馆的「扩展 → 安装扩展」中粘贴：

```text
https://github.com/liushuangls/ST-DialogueRenderer
```

安装后刷新页面，在扩展设置里打开「对话渲染系统」。无需安装酒馆助手，也无需导入额外渲染正则。以后通过酒馆扩展管理中的「更新」按钮更新，再刷新页面生效。

v1.0.2 起入口、子模块和样式依赖使用一致的版本参数，避免更新后浏览器继续读取旧解析代码。

首次迁移前，停用旧版对话渲染管理脚本，以及所有旧版 `[近期]` / `[历史]` 对话渲染正则，然后刷新。插件检测到这些旧实例时会暂停接管并显示提示，避免重复注入和双重渲染。

## 使用

- **启用对话渲染**：同时控制渲染和格式/情绪提示词注入。关闭后恢复酒馆原始显示，已保存的头像和设置保留。
- **最近 AI 回复数量**：默认 3，可填写 1–100。按实际 AI 回复计数，支持连续 AI 发言，用户/系统/工具消息不占名额。超出范围的旧回复不创建气泡或 iframe。
- **头像、情绪与正文美化**：沿用 v8 的角色卡/全局头像、表情差分、主题色、字号、字体、间距、缩进、背景、导入导出与同步管理。

输出协议保持：

```text
<now_plot>
<content>
普通叙述、动作和场景描写。
@bubble:角色完整姓名|平静|[直接说出口的话]
@bubble:角色完整姓名|欲言又止|[*未说出口的心理活动*]
</content>
</now_plot>
```

v1.0.1 起兼容预设或模型在 `]` 后额外追加一个 `|` 的写法，例如 `@bubble:姓名|平静|[台词]|`；显示时不保留该结尾分隔符，聊天原文不变。

用户与其他角色使用相同规则；用户头像的名称应与当前用户名完全一致。

情绪优先参考词池，没有合适的词时允许简短自由描述。池外词原样显示并使用基础头像，不为匹配头像硬凑情绪。只有精确匹配当前词池的词才选择对应差分。

## 渲染顺序与兼容范围

扩展读取酒馆已经完成显示正则、Markdown 和清理的消息 DOM，再处理其中的对话标记。不会将 HTML/JS 大模板插入正则管线，不会重复执行显示正则，也不会改写保存的聊天原文。代码和样式统一加载，消息只生成必要 DOM。

Markdown 使用酒馆已格式化的结果。原脚本独立的「基础/完整 Markdown」开关不再参与二次解析，旧值仍保留在数据中；Markdown 行为在酒馆设置中控制。标题、引用、普通正文和气泡文字跟随全局文字色，角色主题色模式仍可单独作用于台词。

代码块、iframe、折叠详情和专用前端节点不由本扩展接管。若其他规则提前删除或改变了 `@bubble` 的必要结构，插件无法从最终显示结果识别该行。与同样改写整个消息 DOM 的第三方渲染器仍需分别验证，不能把“位于显示正则之后”理解为任意扩展的全局最高优先级。

普通聊天使用消息事件与仅作用于聊天区域的变更观察，合并到一帧处理，自己的 DOM 修改不会触发重复渲染；关闭后停止观察。TauriTavern 启用消息虚拟化时使用 ChatSurface `didCommitContent` 与同步清理，且不同时启动普通观察模式。编辑、切换回复、消息移出近期范围以及卸载都会释放对应视图。

## 数据沿用

保留 `BubbleDialogueAvatarsV8` IndexedDB、`bdv8` 同步文件前缀和原同步格式。同一酒馆来源下安装扩展可以直接读取已有 v8 数据，无需重传头像。首次迁移时可先使用旧管理面板导出一份完整 ZIP 备份。

跨设备仍使用原 `/user/files` 文件及宿主的 `user.files` 同步范围；扩展更新不替代数据同步。原始 v8 脚本与插件应只启用一个。群聊或未选中角色卡时可使用全局头像。

## 开发与验证

直接以原生 ES modules 加载，无构建步骤；`node_modules` 只用于测试，不随安装包运行。

发布时同步更新 `package.json`、`manifest.json` 和插件内 JS/CSS 引用的 `?v=` 参数（包括测试模块的导入）；`check` 会检查版本一致性。仅更新入口 URL 不会使子模块缓存失效。

```sh
npm ci --ignore-scripts
npm run check
npm run preview
```

浏览器回归地址：`http://127.0.0.1:8766/`。页面使用独立测试数据库和模拟宿主，检查共享渲染、前序显示替换、数量控制、开关、编辑、颜色、基础/差分头像与管理面板。不会访问真实酒馆聊天或头像。

自动化测试包含原 v8 数据/同步/迁移/导入导出回归，以及消息数量、DOM 原样恢复、异步头像清理、普通与 ChatSurface 生命周期测试。ChatSurface 使用契约测试；完整真实宿主/第三方扩展组合与移动端仍应进行安装实测。

代码入口：`index.js`；宿主协调：`src/extension.js`、`src/controller.js`；消息装饰：`src/dom-renderer.js`；共享资源：`src/assets.js`；沿用的 v8 管理模块：`src/avatar-manager.js`。
